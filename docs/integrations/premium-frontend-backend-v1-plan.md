## Authority operations during integration

- Hide or disable `authorize_settlement_signing`, any settlement wallet prompt/send control, and `mark_paid`/`mark_failed` submission forms in the premium frontend. Do not invoke these from a browser polling or retry effect. Keep operator credentials out of client code. This is UI availability guidance and does not change server roles or production permissions.
- Default the integration candidate to read-only settlement UI. If a separately approved offline operator rehearsal exposes preparation, label it intent-only, keep it role- and source-gated, and never show a payment or execution affordance. Fixture settlement actions remain blocked in the backend and UI.
- A future signer must enforce the exclusive deadline at signing and submission and consume the backend's fresh authorization for the exact wallet, nonce and payload. The contract enforces coverage expiry. It does not enforce the evidence deadline. Pending, missing, orphaned or ambiguous receipt states keep commitments and require reconciliation.
