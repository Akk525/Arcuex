## Highest-impact issues (behavior unchanged)

### 1. Flat navigation treats all audiences as one

`AppShell` exposes Overview, Coverage, Policies, Capital, Claims, Agent Permissions, Integrations in one strip. Policyholders see capital and integrations; integrators see claims review links; ops sits one click from consumer flows. **Impact:** role confusion, accidental ops discovery, weak journeys.

### 2. No public product story

`/` is a connectivity dashboard, not a landing that explains human vs agent entry points. AGENTS.md historically forbade marketing landing; Nov 20 sprint explicitly wants one. **Impact:** first session starts in instrumentation, not insurance intent.

### 3. Inconsistent visual systems

- Global: zinc + IBM Plex + soft blue radial wash.
- Procurement: bespoke `.proc-*` CSS parallel to Tailwind panels.
- Claims: Panel + StatusBadge + dense mono fragments.
- No shared tokens for space, type scale, surfaces, or status semantics beyond ad-hoc badges.

**Impact:** pages feel like separate demos; hard to extend consistently.

### 4. Language mixes developer and insurance vernacular

Copy jumps between “synthetic fixture,” “RPC,” “Streams webhook ≠ payout authority,” and coverage language. Status labels (SYNTHETIC, MUTATIONS OFF, ADJUDICATION v1) are accurate but compete for attention with journey CTAs. **Impact:** trust and comprehension suffer for human policyholders.

### 5. Auth / empty / error states still uneven in presentation

P0 claims crash is fixed (sign-in-required). Remaining issues are IA/copy: wallet “Sign in” always shown without session summary; empty claims vs no policy vs wrong role share similar zinc/rose text patterns without shared `EmptyState` / `AuthGate` components. **Impact:** cognitive load, harder to extend safely.

### 6. Claims page overloads roles

`/claims` stacks case list, historic receipt, trust boundaries, legacy ledger. Reviewer entry is a top link. **Impact:** policyholder claim tracking buried beside ops/legacy surfaces.

### 7. Procurement is powerful but not wizard-shaped

Coverage is a long panel rather than explicit steps (eligibility → terms → accept digest → approve → bind → confirmed). Transaction state exists in code paths but is not a first-class staged UX. **Impact:** users cannot tell “quoted” from “bound/active.”

### 8. Capital and integrations in primary nav

Capital synthetic ledger and integration health are beta-useful but not first-session for dual primaries. **Impact:** dilutes Protect / Build journeys.

## Information architecture gaps

Missing explicit spaces:

1. **Public discovery** — what Arcuex is; Protect vs Build CTAs.
2. **Policyholder workspace** — overview, coverage wizard, policies, claims (owner).
3. **Builder workspace** — agents, delegations, SDK/integrations.
4. **Ops workspace** — review, authority, capital (role-gated chrome only).

Routes can stay stable; chrome and hierarchy should change.

## Accessibility / responsive gaps

- Focus styles exist for `.procurement` but not globally standardized.
- Nav wraps poorly into a “chip salad” on mobile; no workspace switcher pattern.
- Tables/lists are `<ul>`/`font-mono` dumps without consistent row/header patterns.
- Status color alone (emerald/amber/rose) without text equivalents in places.

## What already works (preserve)

- Exact quote acceptance / immutable digest discipline in procurement.
- Claims auth discrimination (401 ≠ empty) after P0 hotfix.
- Synthetic vs live labeling intent (needs quieter, systematic badges).
- Server-side auth and route paths — redesign must not weaken these.
- Historic settlement as read-only verified receipt (good trust artifact when labeled).

## Priority order for redesign impact

1. Landing + dual entry CTAs  
2. Contextual workspace navigation (Protect / Build / Ops)  
3. Design system primitives (tokens, PageHeader, Button, Status, Empty/Auth)  
4. Coverage wizard clarity (never “active” before confirm)  
5. Claims journey clarity (stages, synthetic, not paid until verified)  
6. Agent management polish  
7. Demote capital/integrations/legacy into ops/builder secondary nav
